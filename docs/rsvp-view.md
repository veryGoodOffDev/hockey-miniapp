# Вид отметок: список и чипсы

Переключатель над отметками в деталях игры меняет сразу три группы: «Буду», «Не будут», «Не отметились». По умолчанию список. Кнопки содержат только иконки с подсказками и доступными названиями «Список» и «Капсулы», а также `aria-pressed`; активная выделяется. Список сохраняет отдельные строки, чипсы используют ширину содержимого и `flex-wrap: wrap`. Длинные имена переносятся внутри капсулы без горизонтальной прокрутки.

Оба вида используют одни и те же элементы `RsvpStatusBlock`: группировку G/D/F, подсветку себя, номера, навыки для админа, цвета команд, награды, меню действий. В списке игроки внутри позиции идут по времени отметки от ранних к поздним. В капсулах внутри позиции первыми идут короткие отображаемые имена (длина в Unicode-символах); при равной длине сохраняется порядок по времени отметки и существующий алфавитный порядок. Данные не мутируются. Переключение меняет CSS-класс и порядок отображения, не перезагружает данные и не сбрасывает выбранную игру, фильтрацию или черновик комментария. Экран/вкладка составов не меняется.

## Сервер и профиль

`players.rsvp_view` — `TEXT NOT NULL DEFAULT 'list' CHECK (rsvp_view IN ('list','chips'))`. Колонка автоматически добавляется через существующий `ensureSchema` при запуске backend; повторный запуск не сбрасывает выбор. Новых таблиц и отдельных ручных миграций нет. `GET /api/me` возвращает поле в `player` через существующий запрос профиля.

Новый `PATCH /api/me/preferences` принимает только:

```json
{"rsvp_view":"chips"}
```

Ответ:

```json
{"ok":true,"preferences":{"rsvp_view":"chips"}}
```

Пользователь определяется существующей Telegram/web-авторизацией; проверка членства соответствует `/api/me`. ID из тела не принимается. Запрос обновляет только собственное поле вида, не меняя имя, позицию, номер, навыки или другие данные профиля. Некорректное значение/дополнительные поля: 400; отсутствующий профиль: 404; ошибка БД: 500. Сохранение обычного профиля по прежнему `POST /api/me` не меняет эту колонку.

## Frontend и сохранение

`useRsvpView` + `rsvpViewPreference.js` показывают выбранный вид сразу. Подтверждённое поле профиля приоритетнее кэша; если поля ещё нет, читается `rsvp-view:v1:<tg_id>` в localStorage. Без значения — список. Отказ localStorage не мешает сохранять на сервере. Для восстановления на другом устройстве достаточно обычного входа, без дополнительных фоновых запросов настройки.

Быстрые нажатия объединяются, запросы выполняются последовательно, устаревший ответ не меняет последний выбор. При сбое режим остаётся выбранным локально, рядом с переключателем появляется сообщение о неподтверждённом сохранении и кнопка «Повторить». Следующий вход использует серверное значение: неподтверждённый локальный выбор не выдаётся за синхронизированный. При размонтировании запрос отменяется, поздние ответы не меняют другой аккаунт.

## Деплой

1. Задеплоить **backend**, дождаться успешного старта и добавления колонки.
2. Задеплоить **frontend** стандартной командой `npm run build`.
3. Открыть игру, нажать иконку «Капсулы», дождаться исчезновения «Сохраняем…», открыть приложение на другом устройстве с тем же профилем.

Обновление сортировки капсул по длине имён и переключателя на иконки требует только деплоя frontend, если первоначальная версия backend уже установлена; значение `chips` в API и сохранённых профилях остаётся прежним.

Новые env-переменные, изменения nginx и WebSocket не нужны. Старый frontend совместим с обновлённым backend. Если обновить только frontend, переключение будет локальным, а серверное сохранение покажет ошибку до обновления backend.

Изменения backend: `src/schema.js`, `src/index.js`, `src/playerPreferences.js`. Frontend: `src/TelegramApp.jsx`, `src/RsvpStatusBlock.jsx`, `src/RsvpViewToggle.jsx`, `src/useRsvpView.js`, `src/rsvpViewPreference.js`, `src/styles.css`.

## Проверки

```bash
node --test backend/src/playerPreferences.test.js webapp/src/rsvpViewPreference.test.js webapp/src/rsvpPlayerOrder.test.js
RSVP_TEST_DATABASE_URL=postgresql://postgres@localhost:5432/hockey_view_checks node --test backend/src/playerPreferences.pg.test.js
npm --prefix webapp run build
# Запустить production preview и отдельно:
NODE_PATH=/path/to/playwright/node_modules node webapp/tests/rsvp-view.browser.cjs http://localhost:4174/
```

PostgreSQL-тест работает только с локальной БД с именем, заканчивающимся на `_checks`, в отдельной схеме с очисткой. Проверяет обновление существующей таблицы, значения по умолчанию, ограничения БД, сохранение после повторного `ensureSchema`, независимость пользователей и остальных полей профиля. HTTP-тест проверяет авторизацию, валидацию и ошибки. Тесты состояния покрывают гонки нажатий, сетевые ошибки, повтор и недоступное хранилище. Браузерный тест использует имитацию API: три группы, немедленное переключение, действия игрока, команды/награды, черновик, ширины 320/390/430, второй сеанс с пустым localStorage, другой аккаунт, ошибка/повтор/перезагрузка и отсутствие изменений во вкладке составов. Production-данные и реальные отметки не менялись.
