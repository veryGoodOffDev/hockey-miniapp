# Ошибки входа и загрузки

Frontend различает отсутствие интернета (если это сообщает браузер), сетевой сбой, таймаут, ошибку HTTP 5xx/429, отказ проверки членства через Telegram, отсутствие доступа, неверные данные входа и неожиданный ответ API. Неизвестная ошибка получает нейтральное объяснение и предложение повторить вход вместо сырого кода `unknown`.

При сетевом сбое/таймауте есть подсказка проверить интернет и попробовать отключить VPN либо сменить его сервер. Браузер не сообщает точную причину сетевого отказа: VPN, DNS, TLS и блокировка соединения могут выглядеть одинаково. Подсказка не утверждает, что виноват VPN. Ошибка сервера и отказ доступа не выдаются за неисправность интернета.

`MainGate` сохраняет код ошибки из `reason` **и** `error`, включая JSON-ответ `ok:false` с HTTP 200. Вход успешен только при `ok:true` и наличии ID профиля. Пустой/неожиданный ответ не пропускает авторизацию. Сетевой сбой обычного браузера также показывает ошибку подключения; форма входа по email открывается при отсутствии/невалидности учётных данных (HTTP 401), как прежде.

`fetchApiCandidates` использует общий бюджет `timeoutMs` для всех резервных адресов и чтения тела ответа. Проверка входа ограничена 12 секундами на весь запрос, а не на каждый адрес. Обычные API-запросы сохраняют бюджет 20 секунд, загрузка файлов — 45 секунд. Быстрый сетевой отказ позволяет попробовать резервный адрес в оставшееся время; HTTP-ошибка не переключает адрес. Запись после таймаута не повторяется автоматически. Внешняя отмена запроса не становится ошибкой подключения.

После входа ошибки загрузки игр сохраняют исходную причину и используют те же сообщения. Сбой загрузки не сопровождается неверной надписью «Предстоящих игр пока нет». Обновление списка позволяет повторить запрос.

Backend, миграции, переменные окружения и nginx менять не нужно: достаточно деплоя frontend.

## Единый экран с инеем

`StartupOverlay` остаётся смонтированным между проверкой доступа в `MainGate` и загрузкой данных в `TelegramApp`. Подписи соответствуют запросам: «Проверяем доступ…», «Загружаем игры…», «Загружаем составы…». Начальный HTML содержит такой же экран с подписью «Подключаемся…», видимый ещё до запуска JS и ожидания Telegram SDK. После монтирования React HTML-заглушка удаляется. Проверенный профиль передаётся в приложение без повторного `/api/me` при запуске; дальнейшие обновления по-прежнему проверяют профиль.

Слой `/frost-overlay.png` раскрывается мягкой CSS-маской от четырёх краёв к центру за 1,8 секунды; центр с `/premiumaward.png` остаётся читаемым. Размер PNG подстраивается под экран, сохраняя все четыре края. Старые SVG-веточки удалены. Маска использует стандартные и `-webkit-` свойства; без поддержки масок остаётся плавное появление. Нет canvas, WebGL, частиц и дополнительных игровых циклов. `prefers-reduced-motion` отключает движение. После готовности экран растворяется за 220 мс, сразу пропуская нажатия в приложение; завершения анимации инея загрузка не ждёт. При ошибке меняется центральный текст и появляется кнопка повтора на том же экране. Неуспешная первичная загрузка игр не открывает приложение до повтора. Запросы запуска отменяются при размонтировании, повтор не добавляет слушатели Telegram.

Вложенные загрузки игры/профиля/списка игроков используют компактный вариант в своём блоке, без полноэкранной орбиты шайбы. Функциональность гостевой ссылки `/rsvp` и входа по email сохранена.

Дополнительная браузерная проверка (те же зависимости и Vite):

```bash
NODE_PATH=/path/to/playwright/node_modules node webapp/tests/frost-loader.browser.cjs
```

Проверяет HTML до запуска JS, сохранение одного DOM-экрана при смене этапов и ошибке/повторе, один запрос авторизации, центрирование, ширины 320/390/430, горизонтальный экран, уменьшение движения, фокус на кнопке повтора и снятие блокировки приложения после загрузки.

## Проверка

```bash
node --test webapp/src/connectionError.test.js webapp/src/fetchApiCandidates.test.js webapp/src/fetchApiResponse.test.js
npm --prefix webapp run build
```

Для проверки полного приложения запустить Vite и отдельно браузерный тест (нужны `playwright-core` и Chromium):

```bash
npm --prefix webapp run dev -- --host 0.0.0.0 --port 5173
NODE_PATH=/path/to/playwright/node_modules node webapp/tests/startup-errors.browser.cjs
```

Браузерный тест имитирует Telegram и все API-ответы, не отправляет запросов в production. Проверяет сетевой сбой, offline, таймаут, HTML/пустой ответ с HTTP 200, HTTP 5xx, ошибки Telegram/доступа/авторизации, неизвестный код, ошибку в поле `error`, повторный успешный вход, браузерную форму входа и восстановление загрузки игр. Таймаут UI ускорен в тесте; модульные проверки используют настоящее прерывание запроса и чтения тела.
