# Посты от лица бота и загрузка Telegram Mini App

В «Админ → Напоминания» редактор кастомного сообщения поддерживает одну картинку JPEG/PNG/WEBP до 10 МБ: выбор файла или вставка из буфера обмена, предпросмотр, удаление картинки. Текст без картинки — до 3500 символов. Подпись под картинкой — до 1024 символов (лимит Telegram sendPhoto). Можно отправить только изображение. Фото и подпись отправляются одним сообщением; данные редактора очищаются только после успешного ответа.

Существующий `POST /api/admin/bot-messages/send` принимает JSON для текста и multipart/form-data (`text`, `photo`) для изображения. Права сохранены: только super-admin, с существующей авторизацией и проверкой доступа. Авторизация проверяется до загрузки файла в память. Backend проверяет фактический формат изображения по сигнатуре и размеру. Telegram InputFile отправляет буфер, публичного хранилища не требуется. История хранит тип вложения и Telegram file_id в существующем meta, синхронизация проверяет подпись через editMessageCaption, удаление работает по прежнему message_id. Токен бота не передаётся frontend.

Деплой backend и frontend, без миграций/новых env. Если API находится за nginx, лимит тела запроса для API должен пропускать фото и multipart: например `client_max_body_size 12m;` в соответствующем server/location. Проверить существующую конфигурацию, затем `nginx -t` и reload при необходимости. Production-конфигурация из этой среды не проверялась.

## Почему мог зависать вход

Найден подтверждённый недостаток кода: запрос /api/me не имел конечного срока ожидания, а проверка членства Telegram могла долго ждать Telegram API. Браузерный вход по bearer не проходит ту же проверку членства. Это возможная причина различия, но точная причина на конкретном телефоне не установлена без сетевых данных/production-логов.

Теперь вход ограничивает каждую попытку HTTP двенадцатью секундами, существующие резервные адреса сохраняются. Остальные JSON-запросы ограничены двадцатью секундами, загрузка файла — сорока пятью. Ограничение действует и на чтение тела ответа. При таймауте мутации не повторяются автоматически на другом адресе. Вход отображает ошибку и «Повторить», предыдущая попытка отменяется при повторе/закрытии экрана. Backend ограничивает getChatMember восемью секундами; таймаут возвращает telegram_unavailable без обхода проверки доступа.

После деплоя открыть приложение заново в Telegram на телефоне. Если войти всё ещё нельзя, сохранить текст появившейся ошибки и сверить backend-лог /api/me, CORS, доступность публичного API и проверку членства; бесконечный загрузчик больше не должен скрывать отсутствие ответа сервера.

Проверки: `npm --prefix webapp run build`, `node --test webapp/src/fetchApiResponse.test.js`, `RSVP_TEST_DATABASE_URL=postgresql://postgres@localhost:5432/hockey_rsvp_checks npm --prefix backend test`. Браузерная проверка использует имитацию Telegram-контекста и контролируемые ответы API, не отправляет сообщений в реальный чат.
