# Ручная награда «Лучший игрок матча»

Администратор открывает завершённую игру → нажимает имя игрока в списке «Буду» → в существующем меню позиции выбирает «Выдать награду».

Кнопка доступна после того, как игра считается завершённой по текущим правилам интерфейса (через два часа от начала), и не показывается у отменённой игры. У выбранного победителя кнопка меняется на «Отменить награду»: она отправляет `best_player_tg_id: null`, снимает значок и оставляет игру без победителя. После отмены награду можно выдать снова. При выборе другого игрока появляется «Переназначить награду» с подтверждением; прежний значок снимается только в этой игре.

Используется существующий защищённый API `POST /api/admin/games/:id/best-player` и поле `games.best_player_tg_id`. Оно хранит одного победителя у каждой игры. Анонимное голосование, его таблицы/результаты и Sheep Coins не меняются.

Значок из `public/sheepawardtiny.jpg` отображается с небольшим отступом справа от имени во всех группах отметок этой игры. Он виден обычным пользователям и при повторном открытии истории, независимо от текущего глобального держателя талисмана. Если победителя больше нет в текущем списке игроков (например, его профиль отключён), имя и значок остаются отдельной короткой строкой перед списком.

При ошибке выдачи/отмены текущее состояние награды сохраняется, а меню остаётся открытым для повтора. После успеха обновляются детали, карточки и уже загруженная история игр.

## Напоминание о трофее за предыдущий матч

В списке игроков следующего матча прежний победитель получает компактную вторую строку внутри имени: полноцветный непрозрачный трофей и «В прошлой игре». Это напоминание принести трофей; оно не выдаёт новую награду и не заменяет яркий значок победителя открытой игры. Один человек может иметь оба значка, если выиграл оба соседних матча. Подсказка показывается в IN/OUT/не отметились; если владельца нет в текущем списке, доступна короткая строка с его именем перед списком.

Существующий `GET /api/game` дополнен `game.previous_game_award`: `{game_id, starts_at, tg_id, name}` или `null`. Backend сначала выбирает непосредственно предыдущую неотменённую игру по `(starts_at, id)`, а затем проверяет её награду и завершение (2 часа). Если награды нет, более старый держатель не подставляется. В отменённой открытой игре подсказки нет. После отмены награды в предыдущей игре подсказка исчезнет при обновлении/повторном открытии следующей. Третья по порядку игра уже смотрит на своего непосредственного предшественника.

Это один дополнительный SQL-запрос параллельно с загрузкой состава; новых запросов браузера, фоновых таймеров и сохранённых копий награды нет. Ошибка необязательной подсказки логируется и не блокирует загрузку игры.

## Деплой

Для напоминания **backend, затем frontend**. Существующий API расширен полем; новые таблицы, миграции, env-переменные и настройки nginx не нужны. Отдельная выдача/отмена награды по-прежнему использует прежний API. Старый frontend совместим с новым backend; новый frontend без обновлённого backend работает, но напоминание не появится.

## Проверка

Проверено полное приложение в Chromium с имитацией Telegram и существующего API: будущая игра без кнопки выдачи, история игр, ошибка/повтор, один победитель, подтверждённое переназначение, разные победители у разных матчей, повторное открытие после перезагрузки, просмотр обычным участником, загрузка фотографии и ширины 320/390/430 px. Дополнительно выполнены существующие тесты сортировки и production-сборка. Во время проверки реальные награды в production не назначались.

Проверка отмены: после выдачи нажать имя победителя → «Отменить награду», убедиться в исчезновении значка и отсутствии победителя после перезагрузки. Другие игры сохраняют своих победителей; повторная выдача доступна.

Для напоминания проверены PostgreSQL-сценарии: непосредственный сосед, пропуск отменённых игр, даты в другом порядке относительно ID, одинаковое время, отсутствие/отмена награды, отсутствие первого предшественника, будущая игра-предшественник и удалённый профиль. В полном приложении с имитацией API проверены приглушённый и яркий значки отдельно и вместе, отсутствие переноса на третью игру, отмена/повторная выдача и мобильные ширины. Команда: `RSVP_TEST_DATABASE_URL=postgresql://postgres@localhost:5432/hockey_rsvp_checks node --test backend/src/previousMatchAward.test.js`.

## Окно при входе для держателя овечки

Все значки награды используют `/premiumaward.png`. При входе в основное приложение `SheepReminder` проверяет `previous_game_award` ближайшей запланированной, ещё не завершившейся игры. Только её держателю показывается модальное окно «Не забудь принести овечку на следующую игру» с изображением и кнопкой «Хорошо». Нативный dialog размещается поверх остальных слоёв приложения, удерживает фокус и блокирует прокрутку подложки. Ошибка необязательного запроса не мешает открыть приложение.

Без галочки окно закрывается до следующего запуска приложения и не появляется повторно при переходах между разделами. Галочка «Больше не напоминать» сохраняется при нажатии «Хорошо» в localStorage текущего устройства/браузера, отдельно для пользователя, награждённого матча и следующей игры. Новая награда не наследует отключение; на другом устройстве настройку нужно поставить отдельно. Очистка данных сайта сбросит настройку. Если сохранение недоступно, окно сообщает об этом и позволяет закрыть его без галочки.

Эта доработка требует **только деплоя frontend**, если backend предыдущей доработки с `previous_game_award` уже установлен. Новых миграций и env нет. Дополнительная загрузка деталей ближайшей игры выполняется один раз при входе/смене ближайшей игры, без polling и записей в backend.

Проверка полного приложения с имитацией Telegram/API, без реальных отправок и награждений:

```bash
npm --prefix webapp run dev -- --host 0.0.0.0 --port 5173
# Во втором терминале, с установленными playwright-core и Chromium:
NODE_PATH=/path/to/playwright/node_modules node webapp/tests/sheep-reminder.browser.cjs
npm --prefix webapp run build
```

Сценарии: держатель/другой игрок, новая картинка, верхний модальный слой, ширины 320/390/430, закрытие и повторный вход, сохранённая галочка, новый контекст награды, отменённая игра/награда, ошибки API и недоступное хранилище.
