# Карточки игроков и история запуска бота

В «Админ → Игроки» список заменён карточками с аватаркой, именем, username/ID, номером джерси, позицией, состоянием доступа и прежними отметками гостя/админа/ENV-админа/премиума. Клик или клавиатурная активация открывает прежнюю форму редактирования. Поиск имени, username, номера и ID сохранён. Без фото или при ошибке загрузки показываются инициалы; изображения загружаются лениво.

Фото для карточки передаётся отдельным `avatar_url` через существующий `photoUrlForPlayerRow`: сохранённый Telegram file ID использует текущий API-прокси, иначе берётся существующий `photo_url`. Исходное `photo_url` остаётся в DTO без изменения, чтобы прокси не попал в редактируемое поле профиля. Telegram file ID в ответ не включается. Новые фотографии у Telegram не запрашиваются автоматически: используется уже сохранённая фотография или заглушка.

## Запуски бота: только основной администратор

Существующий `GET /api/admin/players` добавляет `can_view_bot_status`, равный `true` только при совпадении авторизованного пользователя с серверным `OWNER_TG_ID`. Это не список `ADMIN_IDS`: другие админы, включая ENV-админов, получают новые карточки без истории запусков. Нужные поля не выбираются из БД для них, а презентация дополнительно исключает их из ответа.

Только основной администратор получает в каждой записи:

```json
{"bot_pm":{"started":true,"started_at":"2026-10-24T10:00:00Z","last_interaction_at":"2026-10-24T11:00:00Z"}}
```

Источники — существующие `players.pm_started`, `pm_started_at`, `pm_last_seen`. Существующий бот сохраняет их при личных командах `/start`, `/menu`, `/profile`, `/app` и других поддерживаемых личных взаимодействиях. Открытие Mini App и `last_seen_at` не считаются запуском бота.

Статусы:

- «Запускал бота» — сохранён подтверждённый факт взаимодействия; при наличии дат показываются первый запуск и последнее взаимодействие.
- «Запуск не подтверждён» — нет сохранённого подтверждения. Это не категоричное утверждение, что человек никогда не запускал бота.
- «Без Telegram» — ручной/гостевой/email-профиль или ID, который не соответствует Telegram-пользователю.

Счётчик «Бота запускали X / Y» относится ко всем активным (`disabled=false`) Telegram-профилям. Отключённые и ручные/гостевые/email-профили не входят в знаменатель. Счётчик не меняется от поиска; фильтры запуска применяются поверх прежнего поиска. Доступны «Все», «Запускали», «Нет подтверждения», «Без Telegram».

Факт запуска не гарантирует текущую доставку: учёт блокировок бота в этой задаче не добавлялся. Никаких проверочных личных сообщений и рассылок нет. Уведомления о цветах джерси не реализованы в этой доработке.

## Деплой и проверки

Задеплоить **backend, затем frontend** (`npm run build`). Новых таблиц, миграций и env-переменных нет. Для доступа используется уже существующий `OWNER_TG_ID`: без него история запусков скрыта для всех. Новый frontend со старым backend покажет обновлённые карточки без статусов бота до обновления сервера.

```bash
node --test backend/src/adminPlayerPresentation.test.js webapp/src/admin/playerBotStatus.test.js
npm --prefix webapp run build
# После запуска production preview:
NODE_PATH=/path/to/playwright/node_modules node webapp/tests/admin-players.browser.cjs http://localhost:4174/
```

Тесты проверяют принадлежность основному админу, исключение приватных полей/Telegram file ID, сохранение исходного URL для редактора, классификацию и счётчик. Браузерная проверка использует полный интерфейс с имитацией Telegram/API: фото и обе заглушки, даты и статусы, поиск/фильтры, ширины 320/390/430, открытие и сохранение существующей формы, отсутствие bot-данных у другого ENV-админа. Реальные сообщения и production-профили не менялись.
