# Личные сводки отметок

Используется существующий support-бот. На сервере задайте:

- `SUPPORT_BOT_TOKEN` — токен этого бота (секрет, не хранить в Git).
- `SUPPORT_CHAT_ID` — положительный Telegram ID вашего **личного** чата.
- Получатель должен быть администратором: его ID указан в `ADMIN_IDS` или у его записи `players` установлен `is_admin=true`.
- `TZ_NAME` — часовой пояс, по умолчанию `Europe/Moscow`.

Один раз откройте support-бота своим аккаунтом и нажмите «Старт».
Для этих сводок не нужны команды, webhook или дополнительный polling:
другие пользователи не могут запросить списки. Отрицательные ID групп/каналов
и получатели без прав администратора не допускаются.

На обычном запуске backend очередь обрабатывается примерно раз в 1,5 секунды.
Первое ручное IN/OUT создаёт тихое сообщение для игры; следующие изменения
редактируют то же сообщение. В нём дата и время игры, место, отдельные таблицы
IN/OUT и время последнего взаимодействия для каждого игрока. Неотметившиеся
и автоматические OUT исключены. Сброс убирает игрока из таблицы. Изменения
даты, места или статуса игры также обновляют сообщение. Существующие ручные
отметки на предстоящие игры подхватываются после обновления backend.

ID сообщений и очередь хранятся в PostgreSQL. Ошибки Telegram, включая
ограничение частоты, повторяются с задержкой и не отменяют отметку игрока.
Удалённое владельцем сообщение создаётся заново при следующем обновлении.
`SUPPORT_RSVP_ENABLED=0` отключает доставку; `SMOKE=1` также отключает её.
При очень большом списке действует лимит Telegram в 4096 символов: сводка
показывает, сколько игроков не поместилось; все отметки остаются в базе.

`rsvp_history` сохраняет каждое новое взаимодействие: игру, игрока, прежний
и новый статус, время и признак автоматической отметки. Сброс обозначается
`to_status=null`, повторный IN/OUT — одинаковыми прежним и новым статусами.
История начинается после установки обновления; прошлые переходы не выдумываются.
Текущие старые отметки сохраняют существующий `rsvps.updated_at`.

Для будущих графиков доступен защищённый административный endpoint:
`GET /api/admin/rsvp/history?game_id=123&tg_id=456&after=0&limit=200`.
Фильтры игры/игрока необязательны; `nextCursor` передаётся как следующий `after`.
Ответ содержит события, время игры и имена. Сам интерфейс графиков пока не добавлен.

Проверки:

```sh
cd backend
# Отдельная одноразовая локальная БД, имя заканчивается на _checks.
RSVP_TEST_DATABASE_URL=postgresql://postgres@localhost:5432/hockey_rsvp_checks npm test
```

Интеграционные тесты проверяют реальные триггеры, откат транзакции, массовые
отметки, сохранение ID сообщения, повторы после ошибки и изменение отметки
во время доставки. Telegram в тестах заменён локальным адаптером; реальные
сообщения не отправляются. Без `RSVP_TEST_DATABASE_URL` интеграционный тест пропускается.
