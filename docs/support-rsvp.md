# Личное меню отметок в support-боте

Используется существующий **отдельный** support-бот. На сервере нужны:

- `SUPPORT_BOT_TOKEN` — токен support-бота, отличный от основного `BOT_TOKEN`.
- `SUPPORT_CHAT_ID` — положительный Telegram ID вашего личного чата.
- Получатель должен быть администратором: ID указан в `ADMIN_IDS` или `players.is_admin=true`.
- `TZ_NAME` — часовой пояс, по умолчанию `Europe/Moscow`.

Откройте support-бота и отправьте `/start` или `/games`. После первого запуска
он также показывает кнопку «Показать ближайшие игры». Список содержит до 12
предстоящих игр со статусом `scheduled`, отсортированных по дате. При выборе
кнопки **то же сообщение** заменяется таблицами IN/OUT для выбранной игры.
«← К играм» возвращает список. Неотметившиеся и автоматические OUT исключены.

Пока игра открыта, её таблица обновляется примерно раз в 1,5 секунды. Изменения
в других играх сохраняются, но не создают и не редактируют сообщения. Меню и
выбранная игра сохраняются в PostgreSQL (`support_rsvp_views`), поэтому после
перезапуска сервера продолжается обновление того же сообщения. Старые сообщения
предыдущей версии остаются в чате, но больше не обновляются; их можно удалить
вручную. Новых сообщений на каждую игру больше не будет.

Кнопки обрабатываются только от настроенного аккаунта, в его личном чате и в
текущем сообщении меню. Посторонние аккаунты и группы доступа не получают.

В таблице справа показывается время последнего действия:

- `11.10, 14:35` — IN/OUT или повторная отметка.
- `11.10, 15:10 (смена позиции)` — изменение позиции на игру; изменение позиции
  в профиле также учитывается для предстоящих игр IN без собственного переопределения.

`rsvps.status_changed_at` отдельно хранит время изменения IN/OUT. Смена позиции
его не меняет. `last_interaction_at` и `last_interaction_kind` описывают последнее
действие. В `rsvp_history.interaction_kind` записывается `status` или `position`;
для графиков отметок исключайте `position`. Старые события с одинаковыми статусами,
чья причина неизвестна, отмечены `legacy`: их нельзя достоверно отличить от
смены позиции задним числом. При переносе старых отметок время изменения статуса
восстанавливается из известных переходов истории, либо из старого `updated_at`.

Защищённый административный API истории:
`GET /api/admin/rsvp/history?game_id=123&tg_id=456&after=0&limit=200`.
Фильтры игры/игрока необязательны; `nextCursor` передаётся следующим `after`.
Сам интерфейс графиков пока не добавлен. Для больших списков действует лимит
Telegram в 4096 символов: сводка показывает число не поместившихся игроков.
Полные данные сохраняются в PostgreSQL.

Support-бот теперь получает кнопки через `getUpdates`. Он не должен одновременно
использоваться другим polling-процессом или активным webhook. Код не удаляет
чужой webhook автоматически. Конфликт Telegram 409 виден в логах backend.
Обновления и их offset сохраняются в PostgreSQL. Ошибки отправки повторяются
с задержкой, включая `retry_after`; отметки игроков сохраняются независимо.
`SUPPORT_RSVP_ENABLED=0` или `SMOKE=1` отключают меню и polling.

Деплой требует только обновления backend: таблицы, поля и триггеры создаются
при его обычном запуске. Токены не храните в Git.

Проверки выполняются с отдельной локальной одноразовой базой:

```sh
cd backend
RSVP_TEST_DATABASE_URL=postgresql://postgres@localhost:5432/hockey_rsvp_checks npm test
```

Тесты используют настоящий PostgreSQL и имитацию Telegram API. Они проверяют
меню из 12 игр, переходы в одном сообщении, запрет посторонних callbacks,
сохранение выбранной игры после перезапуска, изменения во время доставки,
откаты, повторы после ошибки и отдельный учёт смены позиции. Реальные сообщения
в тестах не отправляются. Без `RSVP_TEST_DATABASE_URL` интеграционные тесты пропускаются.
