# Управление функциями приложения

В «Админ → Функции» три общих переключателя:

- **Чат приложения** — общий чат, личные переписки и песочница внутри Mini App. Не отключает Telegram-группу, рассылки, сводки составов, ответы и реакции от имени бота в «Напоминаниях».
- **Комментарии к играм** — обсуждение, ответы, реакции, закрепление и просмотр авторов реакций. Скрывается и счётчик комментариев на карточках игр. Ссылка на комментарии открывает обычную карточку игры.
- **Air Hockey в профиле** — скрывает вход в игру и запрещает новые матчи против бота, создание/подключение к PvP-комнатам, реванши и покупку лёгкого уровня. Уже начатые матчи завершаются обычным образом с сохранением результатов и наград. Переподключение участников продолжающегося PvP-матча разрешено. Приглашение не открывает игру, если функция выключена. Баланс SC и общий магазин премиума не обнуляются и не блокируются.

Все функции включены по умолчанию. Настройка общая для всех пользователей, включая администраторов. Её может менять любой существующий администратор приложения (ENV или `players.is_admin`). Отключение не удаляет переписки, комментарии, игровые сессии и баланс.

## Хранение и API

Используется существующая `settings`, ключ `app_features`. Значение — JSON с булевыми полями `chat`, `game_comments`, `air_hockey`. Отсутствующие поля означают `true`. Новых таблиц и миграций нет.

- `GET /api/me` дополнительно возвращает `features`, чтобы сразу показать правильный интерфейс при входе.
- `GET /api/features` — текущие значения для авторизованного пользователя, `Cache-Control: no-store`.
- `PATCH /api/admin/features` — только авторизованный администратор. Тело — непустой частичный объект, например `{"chat":false}`. Неизвестные ключи, строки вместо boolean, массивы и null отклоняются с 400 `invalid_features`. PostgreSQL атомарно объединяет поля; одновременное изменение другого переключателя не теряется.
- Отключённые API возвращают 403 `feature_disabled` с полем `feature`. При недоступности хранилища защищаемые запросы получают 503 `features_unavailable`, а не обходят запрет.

Проверка middleware охватывает `/api/chat/*`, старые альтернативные `/api/messages/*`, `/api/game-comments/*`, начало Air Hockey и покупку лёгкого уровня. Завершение уже созданной bot-сессии остаётся доступным с прежней авторизацией и проверками результата. PvP ticket остаётся доступен с прежней авторизацией для reconnect; WebSocket отдельно проверяет флаг на create/join/rematch, включая уже установленные соединения. Движение/физика действующих матчей не делают запросы настроек на каждый тик.

После успешного сохранения UI администратора обновляется сразу. На других открытых устройствах настройки обновляются раз в минуту, при фокусе окна и возвращении из фона. Чат закрывается при отключении, его poll-таймеры и таймер комментариев прекращают работу. Сетевой сбой при чтении сохраняет последнее известное UI-состояние, сервер продолжает применять актуальный запрет. Ошибка сохранения не переводит тумблер в неподтверждённое положение; можно повторить запрос. Уже выполнявшийся запрос при отключении может завершиться, но содержимое отключённого раздела не показывается.

## Деплой

Сначала backend, затем frontend. Новых env, npm-зависимостей, изменений nginx и ручной миграции не требуется. Все функции остаются включёнными, пока администратор сам не выключит нужную. Старый frontend может показывать старые кнопки, но обновлённый backend уже блокирует отключённые операции.

## Проверки

```sh
node --check backend/src/index.js
node --test backend/src/appFeatures.test.js backend/src/airHockeyPvp/socket.test.js backend/src/airHockeyPvp/rooms.test.js
npm --prefix webapp run build
NODE_PATH=/path/to/playwright/node_modules node webapp/tests/app-features.browser.cjs http://localhost:4174/
```

Тесты HTTP используют локальный Express и макет хранилища; WebSocket — локальный сервер. Браузерный тест проверяет админский интерфейс на 320/390/430 px, скрытие/возврат разделов, отказ сохранения и повтор, остановку polling, восстановление на другом устройстве, обновление при фокусе и закрытие открытого чата. Production БД и Telegram во время проверки не изменяются.
